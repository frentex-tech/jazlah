## Non-negotiable rules
- **Layout:** `services/api/src/modules/<module>/`. Orders, checkout, payments, refunds, wallet and finance use four layers: `api/` (with `controllers/{customer,vendor,kitchen,admin}.controller.ts` and `dto/`), `application/` (one class per use case), `domain/` and `infrastructure/`. Every other module uses `controllers/{customer,vendor,kitchen,admin}.controller.ts`, `<module>.service.ts`, `dto/`, `events/`, and `<module>.service.spec.ts`, and is promoted to four layers when it gains a state machine or money logic. Internal infrastructure (database, jobs, realtime, the event bus, redis, logger, health) lives in `src/infra/` and never imports from modules: a job processor with business logic lives in the module that owns it, and modules publish realtime updates through the publishing port. Route prefixes by audience: `/v1/public`, `/v1/customer`, `/v1/vendor`, `/v1/kitchen`, `/v1/admin`, `/v1/webhooks`.
- **Money** is an integer number of halalas. Prices include 15% VAT. Never use floats for money. All arithmetic on amounts goes through the Money helper in `src/common/money/`. The finance ledger is append-only: entries are never updated or deleted, and a correction is a new entry.
- **Time:** store UTC. Every business rule (cutoffs, capacity, "today", reminders) runs in `Asia/Riyadh` on the server, using `@date-fns/tz`.
- **Order status** changes in one place only: the state machine in the orders module's domain layer. No other code sets an order's status. Capacity changes only through `CapacityService`. Wallet and ledger changes only through their services, inside the caller's transaction.
- **External providers** (mail, SMS, push, payments, storage, delivery, ZATCA, BNPL) are reached only through their port in `src/integrations/<capability>/`, imported through its `index.ts`, with one file per vendor in `providers/`. The payment gateway is Geidea. Payments never fail over to another provider and are never retried blindly: an unknown gateway response marks the payment pending and triggers a status query. Delivery and BNPL calls go to the provider recorded on the shipment or transaction.
- **Webhooks** check the signature, are idempotent by provider event id, and are processed through a BullMQ queue.
- **Money-moving operations** run in one DB transaction with idempotency keys, never in two independent writes.
- **DTOs** use class-validator plus Swagger decorators. Errors are the shared `AppError` and look like `{code, message}`, with the UPPER_SNAKE_CASE code in the code list in `common/errors/` and AR and EN messages.
- **Admin mutations** use `@Audited()` and `@Permissions()`. Every `:id` route checks ownership (IDOR).
- **Cross-module side effects** go through domain events (`domain.entity.action`), not direct calls from controllers.
- **Migrations** are generated by Prisma, committed and reversible. Never edit a migration that's already merged.
- **Swagger:** after changing DTOs, regenerate `services/api/openapi.json` and the clients (`scripts/gen-api-client.sh`) in the same PR.

## Tests (part of done, not optional)
- Unit tests for business logic (pure functions get table-driven tests).
- e2e tests (supertest, fresh DB) for every new endpoint: happy path, validation error, auth/permission and IDOR.
- Concurrency tests wherever the task mentions limits, capacity, coupons, wallet or ledgers.
- Run `pnpm --filter api lint typecheck test test:e2e` and make it pass before reporting.
