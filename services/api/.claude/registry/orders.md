# Registry: Orders and checkout

One line per building block: name, path, purpose; the detail is in that file's doc comment. Listed by the index, `.claude/REGISTRY.md`. Paths are relative to `services/api/`.

- **OrdersModule** — `src/modules/orders/index.ts` — orders (four layers): order creation, the state machine and transition routes, order reads, `OrderPlacedEvent` and `OrderStatusChangedEvent`; exports `TransitionOrderUseCase`, `ORDER_ADDRESS_USAGE` and `ACTIVE_ORDER_LOOKUP` for checkout, customers and auth. Payment expiry, webhook handling and realtime subscribers remain deferred.
- **CreateOrderUseCase** — `src/modules/orders/application/create-order.use-case.ts` — makes an order from a checked `NewOrder` in the caller's transaction; `priceOrder`, `formatOrderNumber` (`JZ-YYMMDD-NNNN`), `initialStatusFor`, `orderTypeOf` are its pure rules in `src/modules/orders/domain/`.
- **OrderStateMachine** — `src/modules/orders/domain/order-state-machine.ts` — one transition table for actor/fulfilment checks and API `allowedTransitions`; marks only COD rejection as capacity-releasing.
- **TransitionOrderUseCase** — `src/modules/orders/application/transition-order.use-case.ts` — locks the order row, performs the state-machine transition, releases capacity on rejection, writes one history row and admin audit record, and publishes `order.status.changed` after commit.
- **OrderStatusChangedEvent** — `src/modules/orders/domain/events/order-status-changed.event.ts` — the status-change fact, published only after the transition commits.
- **Order audit actions** — `src/modules/orders/domain/order-audit-actions.constants.ts` — the admin transition action written to the audit log.
- **OrderRepository** — `src/modules/orders/domain/ports/order.repository.port.ts` — per-day numbering, create/read/list, scoped transition row locks, one status update plus one history insert; implemented by Prisma and `InMemoryOrderRepository`.
- **Order state helpers** — `src/modules/orders/domain/final-order-statuses.constants.ts`; `src/modules/orders/domain/order-transition-rule.type.ts`; `src/modules/orders/domain/order-transition-actor.type.ts`; `src/modules/orders/domain/order-status-change.type.ts` — final states, rule rows, authorized transition actor and persisted transition payload.
- **Order address/activity ports** — `src/modules/orders/domain/ports/order-address-usage.port.ts`; `src/modules/orders/domain/ports/active-order-lookup.port.ts` — answer whether an address or customer has a non-final order; consumed by customers and auth.
- **CheckoutModule** — `src/modules/checkout/index.ts` — the days, the payment methods and `PlaceOrderUseCase` (`POST /v1/customer/orders`, cash on delivery only: one transaction keyed by `Idempotency-Key` with a body hash).
- **Order read use cases** — `src/modules/orders/application/` — `ListCustomerOrdersUseCase`, `ListVendorOrdersUseCase`, `ListAdminOrdersUseCase` (the owner comes from the caller's token, never the query), `FindVendorOrderUseCase`, `FindAdminOrderUseCase`; `toOrderSummaryResponse` in `src/modules/orders/api/`; `PAST_ORDER_STATUSES` is the customer's `past` tab.
